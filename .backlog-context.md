# Web terminal renders corrupted after tab left idle/refocused — no full re-sync on visibilitychange (only on resize/reconnect) (Priority 3 | Status: in_progress)

## Description
## Summary
Leaving a session tab idle/backgrounded and then returning to it shows a corrupted
terminal — overlapping, interleaved characters, especially over interactive TUI
prompts (e.g. Claude's option picker). The session is fine underneath; only the
rendered buffer is desynced. A manual redraw fixes it, so state isn't lost.

Observed on v1.31.1, Chrome, macOS.

## Repro
1. Open a session whose agent is showing an interactive full-screen prompt.
2. Switch to another browser tab / app and leave it a while (tab gets backgrounded/throttled).
3. Return to the session tab → the prompt/options are rendered garbled/overlapping.

## Root cause
`web-app/src/components/sessions/XtermTerminal.tsx` re-syncs the terminal in exactly
two situations:
- on **mount / Reconnect**, and
- when the **container size changes** (`ResizeObserver` → `FitAddon.fit()`).

There is **no `visibilitychange` / refocus handler** anywhere in the terminal path
(confirmed: the only `document.hidden` usages are in `useVcsStatus`, `useSessionVcs`,
and `useReviewQueueNotifications` — none touch the terminal).

When the browser backgrounds the tab it throttles it, and the incremental tmux
stream ("raw-compressed" control-mode deltas) is coalesced/dropped. On return,
xterm.js's buffer has silently diverged from the real tmux pane, so the next partial
repaint (the prompt redrawing its options) paints **over stale cells** instead of a
clean surface → the overlap.

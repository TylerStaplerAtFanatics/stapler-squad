# third_party/tmux submodule is broken, blocking make quick-check tmux build (Priority 3 | Status: in_progress)

## Description
third_party/tmux is committed to main as a plain directory (git tree, only containing BUILD.bazel) instead of a proper git submodule gitlink, even though .gitmodules declares it as a submodule (github.com/tmux/tmux.git @ branch 3.4). Confirmed via GitHub API that main's tree entry for third_party/tmux is type "dir", not "submodule". As a result: (1) `make init-submodules` / `git submodule update --init --recursive` does nothing, since git does not see a gitlink to update. (2) `make quick-check` (and `make test`/`make test-coverage`) depend on $(BIN_TMUX), which depends on third_party/tmux/configure.ac existing, so the build fails immediately with `No rule to make target 'third_party/tmux/configure.ac'` on any fresh clone/worktree. (3) Separately, when third_party/tmux IS manually populated with real tmux 3.4 source, `make build-tmux` prefers the Bazel path (since bazel is installed), which fails with `no repository visible as '@rules_foreign_cc'` — the WORKSPACE/Bazel setup for building tmux via rules_foreign_cc is incompatible with the installed Bazel version's bzlmod default (no MODULE.bazel exists, so bzlmod auto-generates an empty one and cannot resolve rules_foreign_cc). Discovered while working a separate backlog item (categorize-backlog-sessions) whose actual code fix was already complete on main — this blocked verifying make quick-check passes in a fresh worktree.
